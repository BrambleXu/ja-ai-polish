# 日本語ランタイムフロー

次の安定ステップを順に実行する。各完了条件を満たしてから次へ進む。

## F01 — 言語を決める

確認、診断、見出し、説明には日本語を使い、対象本文も指定どおり日本語で出力する。

**完了条件：** 指示言語が一つに決まっている。

## F02 — モードを決める

自然言語からパラメータを読み取り、固定コマンド形式を求めない。

- `brief` は `write`、`text` は `edit` または `detect` に使う。
- `mode`：`auto | write | edit | detect`。既定値は `auto`。
- `scene`：対応シーンの一つ、または `auto`。
- `intensity`：`minimal | standard | aggressive`。`edit` のみ、既定値は `standard`。
- `scope`：`normal | bounded`。`edit` のみ。
- `voice_samples`：任意の日本語サンプル 2～5 件。
- `output`：完成稿と短い説明、または完成稿のみ。

brief があり下書きがなければ `write`、修正依頼なら `edit`、診断だけなら `detect` を選ぶ。
約 3,000 字を超える文章、長さ維持の指定、公開長文、完全な文を削除する可能性がある場合は
`bounded` を使う。

**完了条件：** モードと必要な入力が確定している。

## F03 — シーンを決める

明示されたシーンを優先する。未指定なら媒体、相手との関係、目的から推定し、Scene
Pack を一つだけ読む。選択が文体や結果を実質的に変える場合だけ確認し、それ以外は最も強い
根拠を使う。分類できない一般記事は `public-writing` とする。

**完了条件：** シーンが一つに決まるか、結果を左右する曖昧さを一度だけ確認している。

## F04 — 台帳を作る

brief または原文から、保護対象、事実、意見、主体—行為—対象、条件、否定、約束、
不確実性、制約を抽出する。

不足が事実、責任、文体、結果を実質的に変える場合だけ質問する。ユーザーが補足しない場合は
明示的な空欄を残す。

**完了条件：** 維持すべき命題がすべて台帳に入っている。

## F05 — 診断する

自然さ・文体適合ゲートを通してから、段落ごとにパターン得点と False Positive Gate を
適用する。`write` は初稿後に実行する。

- `0–2`：維持する。
- `3–4`：`detect` で報告し、standard `edit` では維持する。aggressive では慎重に直せる。
- `5+`：修正候補。シーン、声、忠実性の各 Gate を通す。

密度、位置、機能、シーン適合、変更コストを確認する。一つの表現だけなら弱いシグナルとする。
ただし `JA-USAGE-001` または `JA-REGISTER-001` で、文脈上の不一致と同じ命題を保つ自然な
代案の両方がある場合は修正候補にできる。中立的な文脈でも不自然なら `JA-USAGE-001`、選んだ
シーンや相手との関係でだけ不自然なら `JA-REGISTER-001` とし、同じ箇所に両方を付けない。
すでに自然な日本語は維持する。

**完了条件：** 変更候補ごとに観察可能な根拠と安定したルール ID があり、誤検出候補を
すべて確認している。

## F06 — 調整する

文体サンプルがある場合は、繰り返し現れる特徴だけを抽出する。競合は `SKILL.md` の
優先順位で解決する。
書き手の声を Scene Pack の既定スタイルより優先する。明示された読者・関係の要件はさらに
上位とする。サンプルの事実や特徴的な文をコピーしない。

**完了条件：** 今回使う声とシーンの制約が明示されている。

## F07 — 生成または修正する

`write` は台帳とシーンから直接作る。入力にある主体、条件、行動、結果、判断だけを使う。
根拠のない空白は確認するか、見える形で残す。

`edit` は許可された最小限の修正を行う。

- `minimal`：局所修正のみ。段落を並べ替えない。
- `standard`：独立した事実を失わずに構文、接続、重複を調整する。
- `aggressive`：事実を変えずに再構成し、重複を圧縮する。
- `bounded`：完全な文の削除候補を完成稿に残し、別欄に原文どおり引用する。

根拠のない評価や一般的な結びは、同義表現に変えず削除する。文中の事実は直接述べる。短文の
メタ導入は完全に外し、`解説します` を `説明します／お伝えします` に置き換えない。

確信度の高い `JA-USAGE-001` と `JA-REGISTER-001` は `write` と `edit` で直接直す。
`JA-USAGE-001` は不自然な語、語の組み合わせ、構文だけを置き換える。`JA-REGISTER-001` は
場面に合わない代名詞、敬語、丁寧さ、会話調だけを調整する。命題、相手との関係、責任、約束を
維持し、台帳にない行動や経験を加えない。

生成・修正では全シーン共通のレイアウト整合性ゲートを適用する。普通の本文は一つの物理行に
保ち、リスト、引用、表の前後の文はそれぞれ文法的に完結させる。メールの段落、チャットの
行動項目、ユーザーが指定した SNS の改行、ステータスのラベル、リポジトリのテンプレートや
コードは保持する。`technical-article` で完全な Markdown 記事を求められた場合だけ、その Scene
Pack の H1/H2/H3 契約を読み、他のシーンには適用しない。

`detect` は根拠、重要度、ルール ID、説明、修正案だけを返す。修正文を出さず、著者を
推定しない。

**完了条件：** 日本語草稿がモード、シーン、範囲を満たしている。

## F08 — 監査する

草稿と台帳を照合する。

- 数値、日付、版、名称、用語、URL、パス、コマンド、コード、引用。
- 主体、行為、対象、責任、否定、条件、約束、不確実性。
- 評価、効果、原因、結論がそれぞれ特定の台帳項目に基づくこと。
- 文体、シーン制約、許可済み削除、bounded の削除候補。

完了、公開、テスト通過は状態であり、効果や価値の根拠にしない。その後に自然さ・文体適合
ゲート、レイアウト整合性ゲート、残存監査を行い、`5+` の段落を再確認して、安全な差分だけ
直す。語法や文体の修正で行動、経験、関係、責任を変えていないこと、`JA-USAGE-001` と
`JA-REGISTER-001` を同じ箇所に重ねていないこと、物理行をつないだ結果、実際のシーン境界や
保護対象が消えていないことも確認する。

**完了条件：** 保護値と関係にずれがなく、説明のない 5 点以上の段落がない。

## F09 — 出力する

言語別の出力形式とユーザーの次の行動を使い分ける。`publish` または `copy` では成果物だけを
返し、共同編集またはレビューでは成果物の外に短い説明を添えてよい。完全な
`technical-article` の Markdown 成果物は唯一の `#` 見出しから始め、Scene Pack の H2/H3 契約に
従う。他のシーンにはこの見出し規則を適用しない。

**完了条件：** 見出しと説明が日本語で、対象本文も指定どおり日本語になっている。
