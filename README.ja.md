# ja-ai-polish

**自然な日本語に整えます。事実・文体・意図を守ります。**

[English](README.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md)

</div>

brief から自然な日本語を作成するか、事実、文体、用語、責任関係、書き手の意図を変えずに、
日本語の下書きから定型的な AI らしさを取り除きます。

`ja-ai-polish` が診断するのは観察可能な文章上の問題です。AI が書いたかどうかを判定せず、
検出器の回避も目的にしません。

## できること

| ✍️ 直接生成 | 🛠️ 修正 | 🔎 診断 | 🎛️ 調整 |
|---|---|---|---|
| 与えられた事実と制約から、シーンに合う日本語を作成します。 | 下書きを必要最小限の変更で整えます。 | 本文を書き換えず、パターンと根拠を説明します。 | 任意の日本語サンプル 2～5 件から繰り返し現れる特徴を使います。 |

## 対象範囲

仕事のメール、Slack/Teams のメッセージ、SNS 投稿、進捗報告、リポジトリ運用、
Qiita/Zenn の技術記事、チュートリアル、ブログ、note、コミュニティ向け文章に使えます。

## 基本原則

1. 書き手を推測せず、見える問題を診断する。
2. 文体より先に事実を守る。
3. 表現を禁止語ではなくシグナルとして扱う。
4. 媒体、相手、目的からシーンを選ぶ。
5. 一般ルールより書き手のサンプルを優先する。
6. 生成・修正したすべての文章を監査する。

**✍️ 直接生成**

```text
/ja-ai-polish を使って、日本語の Slack 進捗メッセージを書いてください。
事実：API 修正は完了、負荷試験は未実施、担当は佐藤さん、期限は木曜。

```

**🛠️ AI らしさの修正**

```text
/ja-ai-polish を使って、次の日本語の定型感を抑えてください。
数字、製品名、約束はすべて維持してください。mode: edit、intensity: standard。

[下書き]
```

**🔎 診断**

```text
/ja-ai-polish を使って次の日本語を診断してください。書き換えは不要です。
```

## write / edit / detect モード

| モード | 入力 | 出力 |
|---|---|---|
| `write` | 目的、読者、事実、制約を含む brief | 日本語の完成稿と短い生成メモ |
| `edit` | 日本語の下書き | 必要最小限に直した完成稿と修正内容 |
| `detect` | 日本語の下書き | 重要度、ルール ID、根拠、説明、修正案 |
| `auto` | 自然言語の依頼 | 上記モードへ自動振り分け |

`edit` は `minimal`、`standard`、`aggressive` に対応します。長文や文全体の削除候補がある
場合は `bounded` を使い、本文から黙って削除せず候補として分けます。

## パターンマップ

| 検出シグナル | 標準の対応 | 例 |
|---|---|---|
| 冗長な文法、名詞化 | 必要な丁寧さを保ち、直接的な動詞にする | `確認を行います` → `確認します` |
| 根拠のない評価 | 入力にある結果、指標、影響を使い、なければ不足を示す | `非常に効果的です` → 実際の効果を書く |
| 曖昧な判断、責任回避 | 分かっている条件、判断、次の行動を書く | `場合によります` → 分岐条件を書く |
| 接続語の過剰使用 | 論理上の役割がない接続語を外す | `さらに／一方／つまり` の連続 → 自然につなぐ |
| 文章ナビゲーション | 内容から始める | `本記事では〜を解説します` → 主題を直接述べる |
| 定型的な結び | 既存の結果、制約、判断、次の行動で終える | `今後の発展が期待されます` → 予定を書く |
| 翻訳調、誇張表現 | 具体的な主体と行動を書く | `重要な役割を果たす` → 実際の働きを書く |
| 均一な文のリズム | 意味を守れる範囲で情報を組み直す | 同じ `〜です` が4文 → 自然な長短 |
| 具体性や立場の不足 | 入力にある主体、条件、指標、選択を使う | `総合的に判断することが重要` → 選択を書く |
| 機械的な共感 | 関係に合う距離で具体的に答える | `素晴らしい質問ですね` → 直接回答する |

これらは使用禁止表現ではありません。密度、位置、機能、根拠不足、他のシグナルが重なった
場合にだけ修正を検討します。詳しくは[パターン規則](references/de-ai-patterns.md)を参照してください。

## 忠実性の保証

生成・修正の前に、名称、事実、数値、日付、コード、用語、主体—行為—対象、否定、条件、
不確実性、約束の台帳を作ります。完成後は台帳と照合します。不足情報は確認するか明示的に
空け、流暢さのために作りません。

## 書き手の声

2～5 件のサンプルから、文のリズム、文体、主語省略、直接性、句読点、評価語の頻度を
調整します。繰り返し現れる特徴だけを使い、サンプルの事実や特徴的な文を再利用しません。

## 既知の制約

- 自然さは文脈依存であり、表現のブラックリストにはできません。
- 情報の少ない brief から、根拠のある具体性は作れません。
- 法務、HR、学術などの高リスク文書には有資格者の確認が必要です。
- 文章品質を改善する Skill であり、著者を証明するものではありません。
